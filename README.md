# RoboGuard Reproduction

A reproduction and extension of **RoboGuard: Safety Guardrail for LLM-Enabled Robots**.

This repository contains the core RoboGuard implementation reproduced from the original project, together with an isolated **Google Gemini 2.5 Pro integration**.

The current implementation demonstrates the following safety pipeline:

```text
Scene Graph (JSON)
        ↓
OpenAI / Gemini 2.5 Pro
        ↓
LTL Safety Constraints
        ↓
Spot / Büchi Automaton
        ↓
Candidate Action Validation
        ↓
SAFE / UNSAFE
```

##1. Project Overview
RoboGuard is a safety guardrail for LLM-enabled robots.
The system uses a large language model to convert:
Natural-language safety rules
A semantic scene graph
into formal Linear Temporal Logic (LTL) constraints.
These constraints are then converted into a Büchi automaton using the Spot library. Candidate robot action sequences can subsequently be checked against the generated safety specifications.
The reproduced core architecture is:
```text
Safety Rules + Scene Graph
            │
            ▼
      Contextual Grounding
       (OpenAI / Gemini)
            │
            ▼
        LTL Constraints
            │
            ▼
      ControlSynthesis
            │
            ▼
      Spot / Büchi Automaton
            │
            ▼
      Candidate Action Plan
            │
            ▼
      Safety Validation
```

##3. Core RoboGuard Components
###3.1 Contextual Grounding
The contextual-grounding module generates LTL safety specifications from natural-language rules and the current semantic scene graph.
The original implementation is located at:
src/roboguard/generator.py
The original implementation uses the OpenAI API.
The generated response has the following conceptual structure:
RULE
 ├── constraint
 └── reasoning
For example:
G(!goto(construction_area_1))
means that the robot must always avoid the specified region.

###3.2 Robot API
The action abstraction is defined in:
src/roboguard/prompts/api.py
The available actions include:
goto(region)
map_region(region)
explore_region(region, radius)
extend_map(x, y)
inspect(object, query)
replan
answer(answer)
clarify(question)
These actions provide the interface used by the safety-generation and validation components.

###3.3 LTL Safety Synthesis
The formal verification component is implemented in:
src/roboguard/synthesis.py
The ControlSynthesis class:
Receives generated LTL constraints.
Converts the constraints into a Spot-compatible representation.
Generates a Büchi automaton.
Converts candidate actions into formal propositions.
Traverses the automaton.
Determines whether the action sequence satisfies the safety constraints.
The output contains both:
SAFE / UNSAFE
and the safety result at each action.

##4. Example
For the scene graph:
data/perch_small.json
the system can generate constraints such as:
G(!goto(ground_21))
G(!inspect(knife_1))
G(!inspect(hammer_1))
G(!goto(construction_area_1))
A candidate plan:
[
    ["goto", "ground_1"],
    ["goto", "ground_2"]
]
can be validated as safe.
A candidate plan:
[
    ["goto", "construction_area_1"]
]
is rejected when the generated specification contains:
G(!goto(construction_area_1))
The same formal verification component is used regardless of whether the LTL constraints were generated by OpenAI or Gemini.

##5. Gemini 2.5 Pro Integration
A separate Gemini implementation is provided under:
gemini/
The Gemini integration uses:
Google Gemini 2.5 Pro
instead of the original OpenAI contextual-grounding model.
The Gemini implementation intentionally does not modify:
src/roboguard/synthesis.py
or the core formal verification mechanism.
Therefore the comparison is:
                ┌── OpenAI
                 │
Scene Graph ─────┤
                 │
                 └── Gemini 2.5 Pro
                         │
                         ▼
                   LTL Constraints
                         │
                         ▼
                   Same RoboGuard
                   ControlSynthesis
                         │
                         ▼
                    Spot / Büchi
This allows the LLM component to be changed while keeping the formal safety-verification component consistent.
More details about the Gemini implementation are available in:
gemini/README_gemini.md

##6. Gemini Prompt Isolation
The Gemini-specific implementation maintains a separate prompt structure.
The directory:
gemini/identical_gemini/
contains reference copies of the original RoboGuard-based Gemini test implementation.
The active Gemini prompt is maintained separately in:
gemini/prompts.py
This separation is intentional.
It allows the original RoboGuard implementation to remain available as a reference while Gemini-specific prompt modifications can be developed independently.

##7. Important Gemini Action Abstraction
One difference between the execution API and the formal LTL abstraction is the inspect action.
The execution API can contain:
inspect(object_node, vlm_query)
However, the current LTL safety abstraction uses:
inspect(object_node)
Therefore a safety constraint should look like:
G(!inspect(knife_1))
and not:
G(!inspect(knife_1, "*"))
The Gemini-specific prompt explicitly instructs Gemini to follow this formal abstraction.
This prevents the generated LTL formula from being rejected by Spot because of an additional VLM-query argument.

##8. Installation
Python Version
The current reproduction is developed and tested with:
Python 3.12.x
The package metadata specifies:
Python == 3.12.*

Create a Virtual Environment
python3.12 -m venv .venv
source .venv/bin/activate
Upgrade pip:
python -m pip install --upgrade pip
Install RoboGuard:
pip install -e .
The package dependencies are specified in:
requirements.txt

##9. OpenAI Configuration
The original RoboGuard contextual-grounding implementation uses the OpenAI API.
Set the API key as an environment variable:
export OPENAI_API_KEY="YOUR_API_KEY"
Do not place API keys directly in source code.
Do not commit .env files or API keys to GitHub.

##10. Gemini Configuration
For the Gemini implementation:
export GEMINI_API_KEY="YOUR_API_KEY"
Then run:
cd gemini
python gemini_test.py
The Gemini script loads the scene graph from the repository's data directory and passes it to Gemini 2.5 Pro.
